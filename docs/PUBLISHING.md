# Публикация на GitHub Pages

## Какие файлы загружать

В отдельный репозиторий игры можно загрузить **всё содержимое очищенной папки**. `index.html` должен находиться сразу в корне репозитория, рядом с `style.css`, `js/` и `assets/`.

Обязательно для работы сайта:

```text
index.html
style.css
js/
assets/raster/
.nojekyll
```

Для удобства разработки и проверки также оставьте `README.md`, `package.json`, `.gitignore`, `scripts/`, `tests/`, `docs/` и файл запуска Windows. Они не обязательны браузеру, но пригодятся для локального запуска и проверки исходников.

Не переносите игру поверх репозитория другого проекта. При загрузке в новый репозиторий переносите содержимое папки `игра`, чтобы не получить лишнюю вложенность `игра/index.html`.

## Включение Pages

1. Создайте отдельный репозиторий и загрузите подготовленные файлы в ветку `main`.
2. Откройте **Settings → Pages**.
3. В **Source** выберите **Deploy from a branch**.
4. Выберите ветку **main** и папку **/(root)**, нажмите **Save**.
5. Дождитесь успешного завершения публикации. Адрес появится на странице Pages.
6. Откройте выданный адрес и проверьте начало игры, загрузку графики, звук, сохранение и продолжение после обновления страницы.

Подробности: [официальная инструкция GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Что не требуется

- npm install и сборка;
- сервер Node.js или PowerShell на GitHub;
- загрузка локального сохранения;
- Git LFS для текущих размеров файлов.

Локальные сохранения не переносятся на опубликованный адрес автоматически. Текущий файл описывает порядок публикации; сама публикация ещё не выполнялась.
